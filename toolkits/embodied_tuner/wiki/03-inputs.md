# 03 Inputs — what the critic actually reads

Every prompt the critic receives is a fixed stack of blocks assembled
by `critic.build_prompt`. This file lists them in prompt order, gives
each block's schema, and states what each is authoritative for. If two
blocks disagree, use the priority in §10.

## 1. Prompt block order

Rendered top-to-bottom by `CriticPrompt.__str__`
(`critic.py:222-236`):

1. Wiki block — this directory, concatenated in file-name order.
2. Bitter Lessons block (§3).
3. Trial History block (§4).
4. Current knobs + legal ranges (§5).
5. Hard constraints reminder (§6).
6. Memory pressure block — conditional (§7).
7. Metric summary compact (§8).
8. Timeline verbose (§9).
9. Rationale schema — the output shape the critic must emit.
10. Feedback block — appended on retry only.

The wiki is always at the top, so every later block builds on the
definitions in `01-concepts.md`.

## 2. Wiki block

Concatenation of `01-concepts.md` … `08-gotchas.md`. Reading order is
the file order — earlier files do not assume later ones.

Authoritative for: definitions, formulas, decision recipe, per-knob
directions, constraints, anti-patterns.

## 3. Bitter Lessons block

Header: `## Bitter Lessons (permanent — do NOT repeat these mistakes)`.
Populated by `LessonBook`; each lesson was written by a prior round of
this campaign after a failed trial.

Line format:

    - [trial N, FAILURE_MODE] trigger: <what the failed trial did and how it failed>
        rule: <durable directive — what to avoid or require>

Authoritative for: hard constraints on the next delta that survive the
rolling history window. **Do not propose a delta that violates any
listed rule** unless you can point to concrete metric/timeline evidence
that the memory or feasibility envelope has changed since the failure.

## 4. Trial History block

Header: `## Trial History (most recent last)` (or `(none — first
round)` on round 1).

Per-trial line format:

    - trial N: (STATUS,FAILURE_MODE) delta={...} objective=... step_time=...
        rationale: <summary from the trial that proposed this delta>
        metric_excerpt: <one-line MetricTable snippet>
        timeline_excerpt: <one-line timeline observation>
        error_log_excerpt (tail of run_embodiment.log):
        ```
        <tail slice — OOM / WORKER_CRASH / METRICS_MISSING / DIVISIBILITY_VIOLATION only>
        ```

Authoritative for: which deltas have been tried and what they measured.
Deduplicated for the "do not propose the same value again without new
evidence" rule (`05-recipe.md §7`).

`Status ∈ {OK, FAILED}`. `FailureMode` values in §11.

## 5. Current knobs + legal ranges

Header: `## Current knob values and legal ranges`. One line per
tunable knob followed by a `Pinned knobs (DO NOT touch in this loop)`
sub-list.

Line format:

    - <knob>: current=<value> legal=<int in [min,max] | bool | placement string or mapping>

Authoritative for: the baseline against which the proposed delta is
diffed. Values match the config the last trial actually ran with (after
any prior delta was applied).

## 6. Hard constraints reminder

Header: `## Hard constraints (preflight will reject violations)`.
Compact list of the most-often-violated preflight checks, generated by
`critic._render_constraints`. This block is a summary; the full rule
list is `07-constraints.md`.

Authoritative for: nothing new — it is a redundancy safeguard. Consult
`07-constraints.md` for definitive checks.

## 7. Memory pressure block

Header: `## Memory pressure (last trial failed with OOM)`. Emitted
only when `last_failure_mode == "OOM"`. Directs the critic toward
memory-reducing knobs.

Authoritative for: the "next delta must reduce memory" gate. Also see
`06-playbook.md §8` (memory-triage cascade) and `08-gotchas.md §5`.

## 8. Metric summary compact

The smallest possible summary of the last successful trial. Survives
`CriticPrompt.to_debug_text()` — treat it as the minimum evidence base.

Three sub-sections, each optional depending on data availability:

### 8.1 MetricTable Time-section keys

Header: `## Last trial — MetricTable Time-section keys`.
Line format:

    - <key>=<value>

Keys include `env/interact`, `rollout/generate`, `actor/run_training`,
`actor/sync_model_to_rollout`, `actor/recv_traj`, and per-tag rollups.
Values are seconds accumulated over the trial.

Authoritative for: `±10%` sanity-check of the timeline's per-step
attribution. On divergence, trust the timeline (see §9 and §10).

### 8.2 MetricTable Environment-section keys

Header: `## Last trial — MetricTable Environment-section keys`.
Line format:

    - num_trajectories=<int>

Authoritative for: the denominator of `objective = step_time /
num_trajectories`. Do not compute this yourself — cite the value in
this block directly.

### 8.3 Per-component stall fractions

Header: `## Last trial — per-component stall fractions (idle / total window)`.
Line format:

    - <component>: <fraction>

The fraction of the observation window during which the component's
lanes had no active event.

Authoritative for: coarse "who was idle" read. For per-tag detail see
§9.1 (`stall_fraction` per `(component, rank, tag)`).

## 9. Timeline verbose block

Excluded from `to_debug_text()`. Only present when a `TimelineSummary`
was produced by `parser.py` (see §12 for missing-data cases).

Renders up to six sub-blocks in the following order.

### 9.1 Headline tag stats

Header: `## Last trial — headline tag stats (component / rank / tag / count / median)`.
Line format:

    - <component> rank<N> <tag> count=<int> median=<seconds>

Capped at 24 entries. Authoritative for: per-tag baseline durations.

### 9.2 Critical path per global_step

Header: `## Last trial — critical path per global_step`. Prefixed by a
one-paragraph explainer that reminds the reader `actor/recv_traj` is a
blocking-wait on rollout+env, not actor work.

Per-step format:

    - step=<N>  step_span_s=<seconds>
        <component>/r<rank>: real=<seconds>  blocked=<seconds>  real_frac=<0..1>
        ...

`real_s` is actual GPU work; `blocked_s` is waiting on another
component. **The bottleneck is the lane with the largest `real_s`.** A
lane with big `blocked_s` and small `real_s` is a downstream consumer,
not a bottleneck; do NOT propose to shrink it.

Authoritative for: bottleneck identification. **This is the primary
signal.** All later sub-blocks are corroboration.

### 9.3 Per-component bubble

Header: `## Last trial — per-component bubble`. Bubble = `wall −
union(real-busy intervals across all ranks of this component)`;
blocking-wait tags are excluded so `busy_s` reflects real GPU work
only.

Per-component format:

    - <component>: busy_s=... bubble_s=... bubble_frac=... ranks=...
        r<rank>: busy_s=... bubble_s=... bubble_frac=...

Authoritative for: which component's GPU budget can be reduced (largest
`bubble_frac` = most idle wall-clock).

### 9.4 Component call averages (steady state)

Header: `## Last trial — env/rollout steady-state per-call duration
(first 2 calls dropped as warmup)`. Per-component:

    - <component>: mean=<s> min=<s> max=<s> n=<int> (skipped=<int> of total=<int>)

Skips the first 2 events per component (bootstrap warmup) so the mean
reflects steady state.

Authoritative for: the typical per-call cost the critic can compare
against outliers.

### 9.5 Outlier events

Header: `## Last trial — outlier events (per-tag P95, >1s)`.
Per-row:

    - <component>/r<rank> <tag> step=<N> dur_s=<s>  hint=<knob-name>

`hint` links the stall to a tunable knob the critic can flip
(e.g. `env.enable_offload`). Authoritative for: knob suggestions
that map cleanly to a single stall.

### 9.6 Raw excerpts and JSONL

Headers:
`## Last trial — raw timeline excerpts (top-K longest events, runner wrapper excluded)`
and
`## Last trial — raw timeline JSONL`.

Top-K longest events as compact JSON, plus optional per-rank JSONL
files fenced by file stem (see `03 §12` for when JSONL is populated).
Use to cite specific events by (`component`, `rank`, `tag`,
`global_step`, `qualname`, `call_index`).

Required whenever the delta touches `cluster.component_placement`
(dual-source rationale rule — `05-recipe.md §6`).

## 10. Priority when blocks disagree

Consult in this order when signals conflict:

1. `## Last trial — critical path per global_step` (§9.2) — the
   `real_s` decomposition is the single source of truth for bottleneck
   identification.
2. `## Last trial — per-component bubble` (§9.3) — corroborates
   §9.2 by showing which side was idle wall-clock.
3. `## Last trial — component_call_averages` (§9.4) — corroborates
   the per-call cost the parser attributed to each component.
4. `## Last trial — MetricTable Time-section keys` (§8.1) — sanity
   check only; on ±10% divergence with §9.2, trust §9.2 (the
   MetricTable tag is wrapper-noisy).

The `## Last trial — outlier events` block (§9.5) is corroboration for
a decision already made from §9.2 — do not use it as the primary
bottleneck signal.

## 11. Failure mode enum

`Status ∈ {OK, FAILED}`. `FailureMode ∈`
(`toolkits/embodied_tuner/parser.py:73-88`):

| FailureMode              | Meaning                                                                          |
|--------------------------|----------------------------------------------------------------------------------|
| `NONE`                   | Only legal with `Status.OK`.                                                     |
| `METRICS_PARTIAL`        | Trial ran but `--no-profiler` disabled the timeline; cannot win best-config.     |
| `METRICS_MISSING`        | `metrics.log` absent or empty; usually a very early crash.                       |
| `CONFIG_INVALID`         | Synthetic — preflight rejected the delta before launch.                          |
| `LAUNCH_FAILURE`         | Ray / entry-script never started.                                                |
| `OOM`                    | CUDA OOM in one of env / rollout / actor.                                        |
| `WORKER_CRASH`           | Non-OOM crash inside a worker (assertion, segfault, TP init failure, …).         |
| `TIMEOUT`                | Wallclock cap hit; the trial never emitted a `Global Step:` line.                |
| `DIVISIBILITY_VIOLATION` | Synthetic — matched a routing-divisibility assertion; see `07 §2.6`.             |

Failure modes that require a `bitter_lesson` in the critic response
(`critic.py:827-829`):
`OOM, WORKER_CRASH, TIMEOUT, CONFIG_INVALID, DIVISIBILITY_VIOLATION`.

## 12. Missing data cases

- `--no-profiler` disables all `RLINF_TIMELINE*` env vars → the trial
  is `(OK, METRICS_PARTIAL)`. The timeline verbose block is empty; use
  only the metric summary compact block. Cannot win best-config.
- `RLINF_TIMELINE_ACTOR_TRAINING=0` (default for third-party patch
  files) suppresses `actor_forward` / `actor_backward` — only
  wrapper-level `run_training` will exist. `enable_timeline.sh` in this
  toolkit turns actor training on for exactly this reason.
- Timeline directory exists but the tag map is empty → the trial
  probably crashed before the first event flush. Re-classify by
  checking `stderr` / `run_embodiment.log`; usually a WORKER_CRASH or
  OOM masquerading as METRICS_PARTIAL.
- Missing sub-block within timeline verbose → the parser produced no
  events matching that view (e.g. no per-step critical path when zero
  events carry a `global_step`).
